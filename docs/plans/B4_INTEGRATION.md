# Batch 4 integration: binding decisions and the shared layer

**Status.** Design HEAD `2b561a9`. The owner approved batch 4 "as designed": two pod sessions (S1 on an RTX 4090,
S2 numpy only), DINO/CLIP (lane E) deferred to batch 5, about $4-6. This document is binding: where a track design or a
review conflicts with it, this document wins. The shared layer below is implemented (uncommitted until P1); the three
tracks (T1 scoreboard, T2 collapse, T3S spatial) implement their own files against the interfaces in section 3.

Batch 4 in one paragraph: T1 measures what intermediate geometry adds beyond the full output head, per sample. T2 owns
the collapse arm, including the single PRIMARY claim (the owner's hypothesis "collapse predicts how models differ"). T3S
is lane S only (X5 spatial maps). One CIFAR Stage-A instrument extracts all 43 units in one GPU session; confirmation
material is extracted in the same session but SEALED until a Windows freeze commit (P2); S2 opens it once.

### D2. One CIFAR Stage-A instrument
- `scripts/b4_extract.py` extracts every batch-4 CIFAR unit (43) on one GPU in S1. It is built from T2's `t2_extract.py`
  (ResNets through the unchanged `BlockHooks`, hub pinned at `786c16252c0f...`), with T1's layouts, fault splits and guards
  and T3's `maps` mode.
- The 18 old nets are re-extracted in the fit layout. The committed atlas dumps are opened ONLY by the anchor gate (D15).
  D and C therefore come from the same code, rows, dtypes, device and session (T1 review B3 dissolved).
- **Canonical head path:** every analysis reads the stored float32 model logits. Per dump: stored penult W^T + b must
  agree with them (argmax agreement >= 0.99, every disagreement a near-tie with top-2 gap <= 0.05); a failure is fatal for
  the unit. `scripts/b4_weights.py` owns `last_linear()` and `export_head()`; the extractor imports them.
- **Storage:** ref, test, OOD, faults and the 10 discovery corruptions: every GAP tap. Holdout corruptions and extras:
  the X4 set only (first tap, pre, penult). Penult float32 on ref, test and OOD, float16 elsewhere. A finite check after
  every cast. `meta.json` written last; a partial directory makes the extractor refuse, a complete one is skipped.
- **Tap metadata:** `tap_spatial`, `dup_of_penult`, depth fractions. **The pre tap is the last spatial tap that is not a
  copy of the penult, for every track** (layer3.1/3.2/3.3/3.5 for r20/32/44/56; pool5 for every VGG; features.17 for
  MobileNetV2; stage4 for ShuffleNetV2; stage3 for RepVGG).
- **Hub weights:** byte size against the release API (fatal per unit); full sha256 recorded; the 8-hex tag against the
  sha256 prefix (a mismatch makes the unit NOT_EVALUABLE); full-10k accuracy against the README, |delta| <= 0.003,
  measured in `b4_weights.py` before any extraction (fatal per unit; the number is public).

### D7. Discovery -> freeze -> confirmation: two sessions, no freeze commit on the pod
- S1: all GPU work, plus the discovery probes run niced on the 4090's otherwise-idle vCPUs, concurrently with the GPU
  chain. All confirmation material (C, F, F20, K, the R2 eval layouts, the Sconf maps) is extracted in S1 but **sealed**.
  The pod is then terminated; the freeze P2 is a Windows commit; S2 runs numpy work only.
- Why: the pod never pushes, so a pod-local commit is not a public freeze; an idle 4090 during a human freeze costs
  $0.74/h; S2 needs no GPU; rule 6 holds at Stage A (one session, one GPU) and Stage B (anchors replayed in S2); precedent:
  the ANOMALY_H1 confirmation dumps existed before P_A and were read once (pod_atlas.sh:859).
- Discovery reads the b4d re-extractions of the same rows as the existing dumps (reading the old dumps would reintroduce
  mixed instruments).
- **Enforcement:** `atlas/b4_core.open_dump` is the only way a probe opens a dump. A dump is sealed when its path is under
  `results/b4c_` or it holds `SEALED.json`; it opens only in the confirmation phase with `ATLAS_B4_UNSEAL=<P2>`, where P2 is
  an ancestor of HEAD holding `experiments/b4/freeze_P2.json`; every unseal is appended to
  `$ATLAS_B4_CHECK_DIR/unseal_log.jsonl`. In the discovery phase every split whose name contains one of
  `CONFIRMATION_ONLY` = (impulse_noise, glass_blur, zoom_blur, frost, elastic_transform, speckle_noise, gaussian_blur,
  spatter, saturate, exposure_global, soiling) is refused.
- Further rules: the extractor prints only PASS/FAIL for sealed units (never an accuracy or a target); `sealed.json` (sha256
  of every sealed `meta.json`) is committed in R1 and `b4_guard_p2` runs `--verify-seals` against it; in the confirmation
  phase a probe refuses to run if an output for the same (program, unit, layout) exists under any tag (the touched-once
  rule of pod_atlas.sh:830-833).
- Failure paths: extraction code or registry changed between P1 and P2 -> S2 refuses (a new P1' and a GPU re-extraction
  are needed). Probe-code bug fix at P2 -> allowed with a new known-answer test; S2 re-probes every discovery unit first
  (`_p2` tag) and the evaluators refit the frozen procedure on those outputs; the P2-emitted rules become INFO. Discovery
  lane crashed in S1 -> a CPU-only S1b with the same block logic in the discovery phase, before P2.

### D9. Pod block order and GPU exclusivity (`scripts/pod_b4.sh`)
- One GPU job at a time, except two trainings of the same architecture (Stage-1 precedent). Extraction never overlaps a
  training. `--b4s1` refuses any other block and any running GPU job. CPU jobs run with `nice -n 19`,
  `CUDA_VISIBLE_DEVICES=""` and one BLAS thread each. Parallelism P = min(CPU quota - 1, cgroup free memory / peak GB).
  Stream frames go to `/root/b4_frames` (container disk).
- **S1:** guards (P1 <= HEAD, frozen files equal to P1, committed instruments unchanged, fresh check directory) ->
  versions and data report -> pytest and self-tests (hard) -> rebuild check (recorded) -> `b4_weights.py` -> GPU-A
  (anchors, anchor gate hard) -> GPU-B (D, N, Dnew fit; anchor gate for all old nets, per unit; Sdisc maps) -> CPU lane
  starts (anchors first, then T2 on D/N/Dnew, T1 fit, streams on STdisc, T3S on Sdisc) -> GPU-C (training pairs r56
  s31/s32, r20 s31/s32, ls10 x2, wd5e5 x2) -> GPU-D (sealed extraction C -> F/F20 fit+eval -> K -> R2 eval -> Sconf maps,
  each group behind the quota guard; then the seal manifest) -> wait for the CPU lane, `timing.json`, pull, terminate.
- **S2:** guards (P1 <= P2 <= HEAD, P2 files present, frozen files equal to P2, extraction code unchanged since P1, seals
  verified) -> versions, pytest, self-tests -> replay of the anchors at discovery settings (tolerance compare rel 1e-6,
  abs 1e-9, timing and environment fields ignored, to `replay.json`; the S1 outputs under `ATLAS_B4_S1_TAG`, default '',
  against `<ATLAS_B4_TAG>_s2replay`, so a relaunched S2 still compares with S1) -> optional re-probe -> confirmation: T2 on C, K, F,
  F20 (the PRIMARY first); T1 fit and eval on F and F20; T1 fit on C and K; streams on STconf (F, F20, R2 units); T1 eval
  on R2; T3S on Sconf.

### D10. Time limits (batch 3's 1800 s lesson)
- S1 defaults, 3x the upper design estimate and never below 1800 s: extraction per unit 1800 s; training per model
  5400 s; T1 fit 64-d 5400 s; T1 fit wide or any eval layout 7200 s; T2 64-d / wide 1800 / 3600 s; streams and T3S
  3600 s; pytest and each self-test 1800 s. They live in `scripts/pod_b4.sh` only (`B4_LIMITS`, `B4_T_*`).
- Every probe writes per-tap and per-target `timing_s` (the batch-3 failure killed a Stage B at tap 18 with no per-tap
  record).
- S2 limits come from `b4_timeouts.js`: clamp(ceil(3 t_ref max(1, (d/d_ref)^2) rows/rows_ref), 1800, 14400); t_ref =
  the slowest S1 run of the same program on the same family; above 4 h the job is flagged SPLIT and split into per-target
  chunks before P2; the same script writes `peak_gb` per program (sets P).
- Timeouts are per unit and soft; a killed unit writes nothing; the relaunch uses `ATLAS_B4_TAG=_r2` with unchanged code.
  The evaluators find each unit's output under every tag (`''`, `_r<k>`, `_p2`), so a relaunch that split the outputs
  between `''` and `_r2` loses nothing; `tests/test_b4_reg.py` pins its time limits to the defaults even when
  `experiments/b4/timeouts.json` (P2) is present, so the S2 pytest gate is hermetic.
- Bootstrap draws: B = 200 in discovery and in the replay; B = 1000 in confirmation (`b4_core.NBOOT`).

### D12. The PRIMARY claim (owner's hypothesis) and multiplicity
- Units: the 12 sealed C architectures. Four laws per outcome, all fitted by frozen code on D21 (D16 + Dnew5) and frozen
  at P2: const (mean of the full-recipe discovery nets); acc (accuracy only); acc + head (accuracy plus the best head-only
  coordinate among sat_frac_msp_0999, mean logit gap and 1 - mean MSP, chosen by leave-one-run-out); acc + collapse
  (accuracy plus the best LABEL-FREE collapse coordinate among pseudo-label NC1, the cross-validated lambda9/lambda10 and
  the top-9 variance share, chosen by leave-one-run-out, log10 where registered).
- Outcomes (fixed at P1; each needs labels or shifted data): O1 dAUC_joint on clean errors (T1); O2 H10 (T2); O3
  L2-normalised 10-NN AUROC - best head AUROC, CIFAR-100 (T2); O4 mean MSP - accuracy under the 10 discovery
  corruptions (T2); O5 X4 AUROC - best head AUROC at s3 (T1).
- Per outcome: WIN = MAE <= 0.8 x the minimum rival MAE AND rho(pred, obs) >= 0.6 AND the family-demeaned rho > 0;
  LOSS = MAE ratio > 0.9. Verdict: SUPPORTED if >= 3 outcomes WIN; REFUTED if <= 1 WINs and >= 3 LOSE; otherwise MIXED;
  NOT_EVALUABLE if fewer than 4 outcomes have >= 10 units.
- Secondary claims (Holm within T2): the labelled nc1_train version; M-DO3 (mechanism); IC-P2 (instrument check); P2(b),
  P3a/b, P4, P5a-c, P6b, P7, P8, S7; the NC4 mechanism item; the family fixed-effect twins; MP-K (over 4 knob pairs x 5
  outcomes, the frozen acc + collapse law predicts delta-outcome better than the accuracy-only law in >= 15 of 20 cells;
  a pair with |delta acc| > 0.5 pt is INFO). Rule 8 applies (FAMILY-DRIVEN, RULE8-CHECK, the partial on log penult
  dimension). An EXTRAP-dominated result reads "extrapolation holds".

### D14. Shared calibration and statistics
Conformal p = (1 + #{cal >= s}) / (n + 1) (`b4_core.conformal_p`). Calibration uses A in the fit layout and the whole
fit split in the eval layout (T1 review A2). Bands are the exact central 99% of the beta-binomial Beta(floor(alpha(n+1)),
n+1-l) x Bin(n_test)/n_test from the one `betaBinomBand` in `scripts/b4_stats.js`, used by all three evaluators (replaces
T2's 3-SD band). Per-sample unit calls are three-way: ADDS / BOUNDED (upper CI < +0.02) / INCONCLUSIVE
(`b4_core.head_additive_call`). Results are reported in functional units (delta TPR at 5% FPR, delta AURC, false alarms per
1000 frames, CPU ms per 1000 queries, reference bytes). Rule 5: DO-3 bands also as a curve from 0.02 to 0.05
(`betaBinomCurve`).

## 4. Implementation decisions of the integration lead (within the binding decisions)
1. **Lane-S pixels are stored in the maps dumps** (`pixels/<split>.npy`, uint8; registry switch `layouts.maps.pixels`),
   so the spatial probe needs no dataset access and opens only dumps. Cost +0.87 GB (maps 4.4 GB instead of 3.4 GB;
   volume ~46.5 GB instead of ~44.7 GB, still inside the 48 GB guard with the per-group quota check). T3S may switch it
   off at P1 and regenerate pixels from the volume instead.
2. **Time limits live only in `scripts/pod_b4.sh`** (`B4_LIMITS` passed to `b4_reg.py --limits`), because D8 lets S1 run
   at P1 plus changes to those limits only; `b4_reg.py` is frozen.
3. **The P2 re-probe is triggered by probe code only** (`B4_PROBE_CODE`: the probes, `b4_core`, `b4_collapse`,
   `b4_reg.py`), not by evaluator fixes (D8 (e)), which run on Windows.
4. **Head identity gate is relative:** max |penult32 W^T + b - logits| / max(1, max |logits|) <= 1e-4 (float32 GEMM
   error is ~1e-6 relative; an absolute bound fails random-init deep nets with large logits).
5. **Extraction batch 256** (the batch-1..3 extraction batch) and CPU-side preprocessing that is bitwise the PIL path,
   to keep the anchor comparison tight. Pixel factors are cached by image hash in `$ATLAS_B4_FACTOR_CACHE` (container
   disk): they depend on pixels only and are identical for every unit.
6. **Partial dumps:** refused (D2); the operator may relaunch with `ATLAS_B4_MOVE_PARTIAL=1`, which renames the partial
   directory to `<dump>_step_partial_<stamp>` (nothing is deleted; the name matches the pull's `--exclude="dump_step*"`
   and the `.gitignore` pattern `results/**/dump_step*`, so a moved-aside dump is neither pulled nor committed).
7. **The rebuild check runs niced in the background** during GPU-A/B instead of before them (it needs no GPU; saves
   ~10 min of idle 4090).
8. **Trained checkpoints are hashed after GPU-C** (`b4_weights.py --trained` -> `weights_trained.json`); the extractor
   records the full sha256 of every checkpoint it loads in the dump meta.
9. **O1's penult bundle is fixed in the schema** (margin, d1, L2 kNN, Trust Score, relative Mahalanobis, kNN purity at
   10 and 50, LID at the penult), because O1 feeds the PRIMARY and must be fixed at P1.
10. **The committed extraction record is trimmed** (no file list, no dtype map, no ResNet head matrix; for a sealed dump no
    accuracy): the full meta stays in the dump, the seal manifest carries its sha256.
11. **The registry generator is self-contained** (`scripts/b4_make_registry.js`, every number cited in its header) instead
    of reading T2's draft registry, so the committed registry regenerates from the repo alone.
